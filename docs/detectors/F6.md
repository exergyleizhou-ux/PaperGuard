# F6 — Patch Splice (per-channel histogram)

> Detects spliced/inserted image regions by per-channel colour-histogram discontinuity between adjacent 32×32 patches (Bik 2016 manual screening, mechanised).

## What it detects

Detects spliced/inserted image regions by per-channel colour-histogram discontinuity between adjacent 32×32 patches (Bik 2016 manual screening, mechanised).

Cluster: `image_forensics` — findings from detectors in the same cluster
are treated as non-independent during the BH-FDR + severity escalation
in [`combiner.py`](../../src/paperguard/evidence/combiner.py).

## Inputs

This detector requires data shaped as: `image_paths`.

See [`detect()` signature](../../src/paperguard/detectors/f6_patch_splice.py) for
exact type expectations.

## Severity ladder

PaperGuard maps internal scores to the standard five-level Severity:

| Level | Meaning |
|---|---|
| PASS | Not applicable / no signal |
| NOTE | Minor curiosity, archived |
| CONCERN | Single-detector p < 0.01 OR moderate signal |
| SUSPICIOUS | Strong signal OR multi-cluster CONCERN+ |
| CRITICAL | Mathematically impossible result OR cross-cluster ≥ 3 CONCERN+ |

This detector's specific cut-points are in the source file.

## Innocent explanations

Every finding from `F6` carries a non-exhaustive list of plausible
non-fraud explanations. Read them. A flagged finding is **never proof of
misconduct** — it is a request for the author / reviewer / editor to
investigate further with full context.

The current innocent_explanations list lives in
[`f6_patch_splice.py`](../../src/paperguard/detectors/f6_patch_splice.py).

## Known false positives / negatives

| Pattern | Likely outcome |
|---|---|
| Very small sample (N < detector minimum) | Detector marks `applicable=False` (no finding) |
| Data with legitimate structural reasons for the pattern | False positive (use innocent_explanations) |
| Data fabricated by an algorithm that mimics this detector's null distribution | False negative (no detector is silver bullet) |

## Calibration & empirical evidence

| | |
|---|---|
| Shipped in | 2.1.7 (built); 2.1.9 (defaults tightened from N=18 empirical data) |
| Default thresholds | `z_threshold = 6.0`, `min_cluster_size = 8` (the "triage tier") |
| Old defaults | `z=4 / cluster=4` — gave FPR 75 % on N=18 (`recall_image_v2.md`) |
| Effect of calibration | FPR 75 % → 62.5 % at same 70 % TPR; LR+ 0.93 → 1.12 |
| Research mode | Pass `PatchSpliceInput(z_threshold=4.0, min_cluster_size=4)` explicitly to restore old behaviour |
| Empirical doc | [recall_image_v2.md](../recall_image_v2.md) |

The N=18 corpus is too small to claim a definitive LR+ — `cluster=20`
gave even better LR+ on that data but we declined to adopt it as
default to avoid over-fitting to small N.
