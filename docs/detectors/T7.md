# T7 — LLM Perplexity (continuation proxy)

> Measures how confidently a reference LM continues the manuscript text. Low continuation-perplexity is weakly indicative of LLM authorship. Opt-in; requires an LLM API.

## What it detects

Measures how confidently a reference LM continues the manuscript text. Low continuation-perplexity is weakly indicative of LLM authorship. Opt-in; requires an LLM API.

Cluster: `paper_mill_signature` — findings from detectors in the same cluster
are treated as non-independent during the BH-FDR + severity escalation
in [`combiner.py`](../../src/paperguard/evidence/combiner.py).

This detector requires data shaped as: `manuscript_text`.

## Severity ladder

PaperGuard maps internal scores to the standard five-level Severity:

| Level | Meaning |
|---|---|
| PASS | Not applicable / no signal |
| NOTE | Minor curiosity, archived |
| CONCERN | Single-detector p < 0.01 OR moderate signal |
| SUSPICIOUS | Strong signal OR multi-cluster CONCERN+ |
| CRITICAL | Mathematically impossible result OR cross-cluster ≥ 3 CONCERN+ |

This detector's specific cut-points are in the source file.

## Innocent explanations

Every finding from `T7` carries a non-exhaustive list of plausible
non-fraud explanations. Read them. A flagged finding is **never proof of
misconduct** — it is a request for the author / reviewer / editor to
investigate further with full context.

The current innocent_explanations list lives in
[`t7_perplexity.py`](../../src/paperguard/detectors/t7_perplexity.py).

## Known false positives / negatives

| Pattern | Likely outcome |
|---|---|
| Very small sample (N < detector minimum) | Detector marks `applicable=False` (no finding) |
| Data with legitimate structural reasons for the pattern | False positive (use innocent_explanations) |
| Data fabricated by an algorithm that mimics this detector's null distribution | False negative (no detector is silver bullet) |

## Academic basis

Gehrmann et al. (2019) GLTR; Mitchell et al. (2023) DetectGPT; Bao et al. (2023) Fast-DetectGPT. PaperGuard adapts the idea as a continuation-perplexity proxy compatible with chat-completion APIs (the OSS literature mostly used /v1/completions logprobs).

## Calibration & empirical evidence

| | |
|---|---|
| Shipped in | 2.0.15 |
| Default thresholds | `THRESHOLD_NOTE = 20.0`, `THRESHOLD_SUSPICIOUS = 10.0`, `THRESHOLD_CRITICAL = 5.0` |
| Opt-in via | `paperguard scan --perplexity-check` (sets `PAPERGUARD_PERPLEXITY_CHECK=1`) |
| Required endpoint | OpenAI chat-completion API with `logprobs: true` support |
| **Empirically blocked on** | cliproxy `gpt-5.x` variants — all 5 tested in 2.1.10 return responses **without** `logprobs` field. Detector correctly returns NOTE-level "inconclusive" on such endpoints rather than fabricated numbers |
| Pre-flight check | `paperguard doctor --ping-llm` reports endpoint's `logprobs_supported` field |
| LR+ measurement | **Not yet measured** — awaits a GPT-4-class endpoint with logprobs. The v9 dataset (`scripts/recall_test_v9_results.json`) has T7 slots pre-wired for a one-command re-analysis |
| Empirical doc | [llm_detection_v2.md](../llm_detection_v2.md), [t8_endpoint_limitation.md](../t8_endpoint_limitation.md) |
